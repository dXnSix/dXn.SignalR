# State

## Purpose And Usage

Read this file before work in this domain or subdomain and update it when the current technical shape changes.

## Current Technical Shape

Connection setup negotiates first, opens a WebSocket, completes the SignalR handshake, and exposes transport-owned storage. Liveness (`src/communication/liveness.rs`, shared): both targets read the handshake response within `handshake_timeout` (default 15 s; native skips WebSocket Ping/Pong frames while waiting) and validate it with one parser (an `error` field, a hub message, an empty or malformed response fail `connect`; hub messages sent in the same frame are kept for the receiver); a keep-alive Ping (JSON `{"type":6}` record, MessagePack framed `[6]`, never tracked for stateful replay) goes out after `keep_alive_interval` (default 15 s) without outbound frames, including during native stateful backpressure; silence for `server_timeout` (default 30 s) is a dropped transport (reconnect allowed, policy or manual handler), never a local close. Natively the writer task sends Pings and the receiver waits with `timeout_at` on a shared tracker clocked by `tokio::time::Instant`; in the browser the per-socket receiver task also drives Pings and the server timeout on the monotonic `performance.now()` clock (one task per socket instead of a separate liveness task). Every liveness duration is accepted as in the .NET client (P2 of `production-grade-client`): `SignalRClient::new` logs warnings for values that cannot work, and a zero keep-alive interval or server timeout acts as 1 s (the .NET timer tick). Natively every connection is bound to a Tokio runtime (`with_runtime_handle`, else the ambient runtime at `SignalRClient::new`, else an error before I/O); negotiate, connect, reconnects, policy delays and dropped-stream cancellation run on it, each physical connection has a runtime-owned writer task (owns the sink, stateful tracking/backpressure, Acks on a priority channel) and receiver task, and the public futures only wait on runtime-agnostic primitives, so they can be awaited from any executor. The stateful buffer's transport generation stops writers of a lost transport from tracking frames after a resume. The buffer also logs payload-free `debug` sequencing records on the `rayx_signalr::stateful` target, each starting with `generation=<n>`: tracked outgoing ids, received ids with `accepted`/`duplicate`, Acks sent and received, Sequence messages, resend ranges with `resend-finished`/`resend-failed`, and rejected Acks, Sequences or messages with the reason; both receivers decode Ack/Sequence frames without validation and apply them through `StatefulMessageBuffer::receive_control`, so malformed and zero ids are traced too. Native Tokio and browser WASM share one lifecycle machine (`Lifecycle` in `reconnection.rs`: NotStarted, Connecting, Connected, Reconnecting, Paused, Disconnected, LocalClosed with a generation per start and reconnect; native wraps it in `ReconnectCoordinator`, the browser in a `Cell`), exposed as public `ConnectionStatus` via `SignalRClient::status()`, plus no-retry/constant/linear/exponential/`DefaultRetryPolicy` (0, 2, 10, 30 s) policies, automatic reconnect, and manual handler control; automatic, manual and resume runs share one generation-checked attempt loop (`FirstAttempt` decides whether the first attempt waits for the policy). `pause()` supersedes any running reconnect and ends the transport (stopping keep-alive and automatic reconnect); sends fail while paused; `resume()` from Paused or Disconnected attempts immediately, then follows the policy; repeated pause/resume are no-ops and `Closed` rejects both. Ordinary pause closes with a WebSocket Close and fails pending work with `ErrorKind::Paused`. Stateful pause: native drops the transport without a Close (the writer stops cooperatively, so a frame already in the replay buffer is never reported failed) and the server keeps the logical connection while it holds the disconnected connection; browsers cannot avoid the closing handshake, so a browser stateful pause ends the logical connection (all pending work fails). On both targets a disposed stateful buffer (browser pause, terminal close, exhausted automatic or resume attempts) makes the next attempt negotiate a fresh stateful connection (`StatefulMessageBuffer::renew`, new transport URL); a resume run that gives up ends the logical connection like exhausted automatic reconnect. A local close (`disconnect`/`stop` on any handle, or dropping the last handle) supersedes and cancels a running start or reconnect (`Runs` abort handles), a pause or a manual-mode disconnection, disposes the stateful buffer and fails pending work; since P2 it is no longer terminal: `start` connects again. Every policy run that gives up (automatic, manual `reconnect_with_policy`, `resume`) ends the logical connection on both targets, and a native run stops once every client handle is dropped (reconnect attempts never hold the connection state across network I/O). Native lifecycle transitions and connection-state writes happen under the state lock, a dropped transport is ignored unless its connection generation is current, and reconnect runs re-check generation ownership after every delay and before each attempt. Ordinary reconnect performs fresh negotiation plus one handshake and fails pending work without replay. Opt-in stateful reconnect resumes the same logical connection token without a second handshake, replays bounded serialized frames, and suppresses duplicates. Since P4 (D20, the .NET WebSocket transport's behavior) an ungraceful loss of a stateful transport is resumed once, at once and outside the policy and the handler (`common::resumes_transparently`: not after a server Close, a server timeout or a protocol violation): natively `transport_dropped` → `resume_transparently` puts the state in `DisconnectionReason::Resuming(writer)` (lifecycle stays `Connected`, same generation, no hook), supervised so `pause`/local close cancel it, and installs the resumed connection on pre-created `WriterChannels`; the browser's `socket_closed` spawns `resume_transparently` (install with no await after the resend). Sends during a resume track as `TrackResult::Held` (buffer `detached` from `disconnected()` until `begin_resend`) and go out with the resend; client-result replies use the resuming writer; a native send whose transport was lost before it was accepted (`Unsent::Stale`) is retried by `ConnectionWriter::send_current` only within the logical connection its first writer belonged to. A failed resume disposes the buffer and continues in `connection_ended` (policy with a fresh negotiate, handler, or `Closed`), which also disposes the buffer for every non-resumable end. `pause()` cancels every run in flight on both targets (`Runs` keys runs uniquely). Local close and terminal server close suppress reconnect. A server Close without reconnect permission fails pending work, moves the coordinator to `Disconnected` (`remote_close`, invalidating in-flight generations) and, in manual mode, still calls the disconnection handler with `ReconnectionHandler::server_allows_reconnect() == false`, whose `reconnect`/`reconnect_with_policy` then refuse. In manual mode a reconnectable drop fails pending work before the handler runs (a stateful connection reaches the handler only after its transparent resume failed). Pending invocations always complete: `fail_pending` and action disposal complete them with an error and end open streams. Lifecycle errors are typed on both targets: a local close fails work with `ConnectionClosed`/`CloseReason::Local`, a terminal server close with `ConnectionClosed`/`CloseReason::Server` carrying the Close message's error and `server_allows_reconnect() == Some(false)`, a run that gives up with `ConnectionClosed`/`CloseReason::ReconnectExhausted` (last attempt as `source()`), a dropped transport or ordinary reconnect with `Transport`; sends fail with `Paused` while paused, `Transport` while reconnecting or after a manual-mode drop, and with the stored close error once closed. The manual-mode `ReconnectionHandler::reason()` carries the error that ended the transport (`Transport`, `Timeout`/`ServerTimeout`, the server's `ConnectionClosed`, or `Protocol`). `SignalRClient::disconnect(&self)` stops the connection for every handle like the .NET client's `HubConnection.StopAsync` (`Communication::disconnect` closes unconditionally); dropping a handle calls `Communication::release`, which closes only for the last owner (both targets count owners: native an atomic `_owners` in `ClientInner`, where `release` and `Drop` give ownership up with one decrement, the owner that takes it to zero closes once behind a `_released` swap, a last owner dropped without `release` closes on its runtime, and a weak handle joins only while the count is above zero; browser an `Rc<Cell>` count), so clones, live `InvocationContext`s and open streams keep a dropped client alive, while registered callbacks and hooks never do (the callback registry holds a `WeakSignalRClient`).

Since P2 (the .NET `HubConnection` lifecycle): `SignalRClient::new` builds an unstarted client (validation only) and `start()` runs a fresh negotiation through the shared attempt path; `connect`/`connect_with` are `new` plus `start`; `start` is `InvalidState` while connecting/connected/reconnecting/paused, restarts after a stop, a server close or exhausted attempts (always fresh, so no logical token is reused), and a failed start leaves `Disconnected` with calls failing `InvalidState`. A start always disposes a resumable stateful buffer and fails old pending work before it publishes its attempt. The stateful buffer is "active" only while not disposed: it is created disposed and renewed only when a negotiation accepts stateful reconnect, so a server that declines it keeps the logical connection ordinary on both targets. Calls made while a start or reconnect attempt is in flight wait for it (`AttemptOutcome`; natively `DisconnectionReason::Attempting`, in the browser `Shared::attempt`) and run on the new connection or fail with the attempt's error (`invoke` returns its send error, not the error the ended run fails pending work with); during policy delays calls fail at once; replies to client results never wait. Lifecycle hooks (`hooks.rs`): `Closed`, `Reconnecting`, `Reconnected`, raised natively under the state lock (a run's `Reconnected` while its connection installs), run on their own task in raise order (natively on the Tokio blocking pool), panics isolated; `Closed` once per established connection (`None` after a stop, `Canceled` when a stop interrupts a reconnect). A drop the policy allows no attempt for (the default `NoReconnectPolicy`) ends the connection at once: no `Reconnecting`, pending work fails with `Transport`, `Closed(reason)`. Policies get a `RetryContext` (drop reason first, then the last attempt's error) through `ask_policy`; a panicking policy ends the run. `connection_id()` is kept with the lifecycle (natively in the coordinator's mutex) and returned only while connected; a stateful resume keeps it. `stop().await` and `disconnect()` close gracefully: natively the writer (`WRITER_GRACEFUL`) sends queued frames, a SignalR Close message and then the WebSocket Close; the browser sends the Close message and closes once `bufferedAmount` is 0 (WebKit can drop a binary frame queued right before `close()`); both bounded by the close timeout (5 s).

Suspension detection (S10, D9, R9.C1):

- **Clock:** `liveness.rs` `LivenessClock<S: ClockSource>` is sleep-inclusive and never decreases. It follows the monotonic clock and adds wall-clock time the monotonic clock missed (a jump of more than 1 s between readings); a backwards wall clock is ignored. Native: `NativeClock` (Tokio `Instant` + `SystemTime`) per `ConnectionLiveness` inside the `Timeline` mutex, with `instant(at) = now + (at - clock.now())`. Browser: a thread-local `LivenessClock<BrowserClock>` (`performance.now` + `Date.now`) behind `now_ms()`.
- **Wakes:** receive loops wake at least every `LIVENESS_TICK` (1 s, the .NET timer) unless the transport has inherent keep-alive (Long Polling). An elapsed wait runs `LivenessTracker::check_wake(max(wake, waiting_since), now)`:
  - lateness up to the keep-alive interval is `OnTime`;
  - otherwise `SuspendedPing` sends a control Ping and falls through to the Ack flush;
  - or `SuspendedDropped` (silence of at least the server timeout) breaks with `suspended_timeout` = `Error::timed_out(ServerTimeout)`. As .NET `OnServerTimeout`, it is not resumed and the policy runs.
- **ASP.NET Core:** its client timeout calls `AbortAllowReconnect`, which ends the hub connection itself, so no client can resume a stateful connection after a suspension longer than that timeout.
- **Tests:** `#[cfg(test)]` `WALL_SKEW` thread-local simulates device sleep in the `suspension_` loop tests.
