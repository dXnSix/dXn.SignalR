# State

## Purpose And Usage

Read this file before work in this domain or subdomain and update it when the current technical shape changes.

## Current Technical Shape

Connection setup negotiates first, opens a WebSocket, completes the SignalR handshake, and exposes transport-owned storage. Liveness (`src/communication/liveness.rs`, shared): both targets read the handshake response within `handshake_timeout` (default 15 s; native skips WebSocket Ping/Pong frames while waiting) and validate it with one parser (an `error` field, a hub message, an empty or malformed response fail `connect`; hub messages sent in the same frame are kept for the receiver); a keep-alive Ping (JSON `{"type":6}` record, MessagePack framed `[6]`, never tracked for stateful replay) goes out after `keep_alive_interval` (default 15 s) without outbound frames, including during native stateful backpressure; silence for `server_timeout` (default 30 s) is a dropped transport (reconnect allowed, policy or manual handler), never a local close. Natively the writer task sends Pings and the receiver waits with `timeout_at` on a shared tracker clocked by `tokio::time::Instant`; in the browser the per-socket receiver task also drives Pings and the server timeout on the monotonic `performance.now()` clock (one task per socket instead of a separate liveness task). Invalid durations (zero, or server timeout not greater than keep-alive) fail `connect` before I/O. Natively every connection is bound to a Tokio runtime (`with_runtime_handle`, else the ambient runtime at `connect`, else an error before I/O); negotiate, connect, reconnects, policy delays and dropped-stream cancellation run on it, each physical connection has a runtime-owned writer task (owns the sink, stateful tracking/backpressure, Acks on a priority channel) and receiver task, and the public futures only wait on runtime-agnostic primitives, so they can be awaited from any executor. The stateful buffer's transport generation stops writers of a lost transport from tracking frames after a resume. The buffer also logs payload-free `debug` sequencing records on the `rayx_signalr::stateful` target, each starting with `generation=<n>`: tracked outgoing ids, received ids with `accepted`/`duplicate`, Acks sent and received, Sequence messages, resend ranges with `resend-finished`/`resend-failed`, and rejected Acks, Sequences or messages with the reason; both receivers decode Ack/Sequence frames without validation and apply them through `StatefulMessageBuffer::receive_control`, so malformed and zero ids are traced too. Native Tokio and browser WASM share one lifecycle machine (`Lifecycle` in `reconnection.rs`: Connected, Reconnecting, Paused, Disconnected, LocalClosed with a generation per reconnect; native wraps it in `ReconnectCoordinator`, the browser in a `Cell`), exposed as public `ConnectionStatus` via `SignalRClient::status()`, plus no-retry/constant/linear/exponential/`DefaultRetryPolicy` (0, 2, 10, 30 s) policies, automatic reconnect, and manual handler control; automatic, manual and resume runs share one generation-checked attempt loop (`FirstAttempt` decides whether the first attempt waits for the policy). `pause()` supersedes any running reconnect and ends the transport (stopping keep-alive and automatic reconnect); sends fail while paused; `resume()` from Paused or Disconnected attempts immediately, then follows the policy; repeated pause/resume are no-ops and `Closed` rejects both. Ordinary pause closes with a WebSocket Close and fails pending work with `ErrorKind::Paused`. Stateful pause: native drops the transport without a Close (the writer stops cooperatively, so a frame already in the replay buffer is never reported failed) and the server keeps the logical connection while it holds the disconnected connection; browsers cannot avoid the closing handshake, so a browser stateful pause ends the logical connection (all pending work fails). On both targets a disposed stateful buffer (browser pause, terminal close, exhausted automatic or resume attempts) makes the next attempt negotiate a fresh stateful connection (`StatefulMessageBuffer::renew`, new transport URL); a resume run that gives up ends the logical connection like exhausted automatic reconnect. A local close (`disconnect` on any handle, or dropping the last handle) is terminal in every state: it supersedes a running reconnect, pause or manual-mode disconnection, disposes the stateful buffer and fails pending work. Every policy run that gives up (automatic, manual `reconnect_with_policy`, `resume`) ends the logical connection on both targets, and a native run stops once every client handle is dropped (reconnect attempts never hold the connection state across network I/O). Native lifecycle transitions and connection-state writes happen under the state lock, a dropped transport is ignored unless its connection generation is current, and reconnect runs re-check generation ownership after every delay and before each attempt. Ordinary reconnect performs fresh negotiation plus one handshake and fails pending work without replay. Opt-in stateful reconnect resumes the same logical connection token without a second handshake, replays bounded serialized frames, and suppresses duplicates. Local close and terminal server close suppress reconnect. A server Close without reconnect permission fails pending work, moves the coordinator to `Disconnected` (`remote_close`, invalidating in-flight generations) and, in manual mode, still calls the disconnection handler with `ReconnectionHandler::server_allows_reconnect() == false`, whose `reconnect`/`reconnect_with_policy` then refuse. In manual mode a reconnectable ordinary drop fails pending work before the handler runs (stateful pending work waits for resume). Pending invocations always complete: `fail_pending` and action disposal complete them with an error and end open streams. Lifecycle errors are typed on both targets: a local close fails work with `ConnectionClosed`/`CloseReason::Local`, a terminal server close with `ConnectionClosed`/`CloseReason::Server` carrying the Close message's error and `server_allows_reconnect() == Some(false)`, a run that gives up with `ConnectionClosed`/`CloseReason::ReconnectExhausted` (last attempt as `source()`), a dropped transport or ordinary reconnect with `Transport`; sends fail with `Paused` while paused, `Transport` while reconnecting or after a manual-mode drop, and with the stored close error once closed. The manual-mode `ReconnectionHandler::reason()` carries the error that ended the transport (`Transport`, `Timeout`/`ServerTimeout`, the server's `ConnectionClosed`, or `Protocol`). `SignalRClient::disconnect(&self)` stops the connection for every handle like the .NET client's `HubConnection.StopAsync` (`Communication::disconnect` closes unconditionally); dropping a handle calls `Communication::release`, which closes only for the last handle (native `Arc` strong count, browser owner count), so clones, registered callbacks and live `InvocationContext`s keep only a dropped client alive.
