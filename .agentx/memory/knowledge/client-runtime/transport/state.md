# State

## Purpose And Usage

Read this file before work in this domain or subdomain and update it when the current technical shape changes.

## Current Technical Shape

Shared `HttpClient` posts to SignalR negotiate version 1, selects WebSockets with the protocol-required transfer format, and constructs connection data. Stateful opt-in adds `useStatefulReconnect=true` to negotiation and retains the negotiated connection token across physical transport replacement. Negotiation (`src/communication/negotiation.rs`, shared by both targets over an injected request function) classifies each response as connection, redirect (`url` + optional `accessToken`, up to 100, queries and the stateful flag kept) or `error`, lets a redirect token replace the configured credentials for the next negotiate and the transport (`ConnectionRecipe::transport_authorization`), and derives the ws/wss URL from the final URL with percent-encoded `id`/`access_token`; `skip_negotiation()` connects directly (with stateful reconnect it disables stateful reconnect and warns, as .NET). A negotiate response without `negotiateVersion` is v0; a classic ASP.NET SignalR response gets the official explanation. Ordinary reconnect renegotiates from the configured endpoint; stateful resume reuses the negotiated transport URL. Native negotiate is one hyper HTTP/1.1 POST over the connection's own TCP or rustls stream (non-2xx errors carry a bounded, credential-redacted body excerpt); the native WebSocket is `tokio-websockets` with `Connector::Rustls`. Each secure native connection builds one rustls `ClientConfig` at `connect` (`src/communication/tls.rs`) with an explicit provider (`tls-aws-lc-rs` over `tls-ring`) and verifier (`tls-platform-verifier` by default, `tls-webpki-roots` bundled roots, `use_webpki_roots()` per connection; Android extra roots switch to webpki) and shares it with every negotiate, WebSocket connect and reconnect; extra PEM roots are validated before I/O and builds without TLS features reject secure endpoints. Transports (S6, D5): `with_transports(Transports)` (bit set, `all()` default); `negotiation::select_transports` keeps the server's `availableTransports` order, filters by the configured set and the transfer format (Server-Sent Events text only) and starts all three (S8; Server-Sent Events skipped for MessagePack, and MessagePack with Server-Sent Events alone fails `new` with `Configuration`/`with_transports`); `transports_failed` names every attempt with its reason in the message (.NET `AggregateException` style), each skip recorded as a `TransportAttempt`; `negotiation::start_with_fallback` (shared by both targets) starts the first candidate, renegotiates for the next after a failed start with `ConnectionRecipe::for_transport` (stateful reconnect only for WebSockets), records a failed renegotiation for its transport, and ends with `transports_failed` (one failure keeps its error, else `TransportUnavailable` with every attempt). Stateful reconnect only when WebSockets is chosen (ASP.NET Core 10 answers `useStatefulReconnect` whatever transport follows; its Server-Sent Events do not resume). `skip_negotiation` needs `Transports::WEB_SOCKETS` alone and stateful needs WebSockets (validated in `new`). Natively `transport_tokio.rs` puts WebSockets behind `TransportSender`/`TransportReceiver` (`Sink<Message>`/`Stream` with crate errors; control frames filtered in the WebSockets arm; `kind()`), `client_tokio` splits `start_transport` and `handshake`; in browsers `browser_transport.rs` wraps `BrowserSocket` in `BrowserTransport` (`start`, `kind()`). Connection-state errors carry no transport; a lost call takes its cause's transport. Access tokens (S5, D26): `Authentication::resolve` asks the factory before every negotiate request until a redirect issues the token; the negotiated recipe keeps transport credentials only for a redirect token (or static auth), so native `current_transport_authorization` asks the factory again for every upgrade and browsers replace the WebSocket URL's `access_token` (`fresh_transport_token`, `negotiation::with_access_token`) on every open. Stateful resumes use the negotiated recipe stored with the resume URL (native `TransportTarget` in the shared endpoint, browser `Shared::transport_recipe`), so a redirect's token covers the whole logical connection. A negotiate timeout reads `negotiate timed out after <bound>` without the URL. The native negotiate and WebSocket-open futures are boxed (debug-build connect futures overflowed 2 MB test stacks). Native clients send `Authorization` on the WebSocket upgrade and never put the token on the URL (`bearer_in_query` is browser-only). Request headers are composed by `src/communication/headers.rs::compose`, identically for native negotiate, the native upgrade and the browser fetch, as .NET `HttpConnection`: defaults (official `User-Agent` `RayX SignalR/<maj.min> (<version>; <OS>; Rust|Browser; Unknown Runtime Version)`, browsers as `X-SignalR-User-Agent`; `Accept: */*` on native negotiate), then `with_header` values replacing same-named ones (empty `User-Agent` removes it), then forced `X-Requested-With: XMLHttpRequest`, then the credentials' `Authorization`; `validate` rejects invalid and transport-owned names (`Host`, `Content-Length`, `Connection`, `Upgrade`, `Transfer-Encoding`, `TE`, `Trailer`, `Keep-Alive`, `Proxy-Connection`, `Sec-WebSocket-*`) before I/O without echoing values. After each handshake (not a stateful resume) the writer sends an initial Ping, except over Long Polling (that Ping makes ASP.NET Core start its client timeout). The native HTTP transports share `http_transport_tokio.rs` (`Target`, `Lane` with `request` and `open_stream`, `Credentials` = the negotiate token from `ConnectionRecipe::http_transport_authorization` shared by every request and refreshed once after a 401, `authorized`, `status_error`, `batch`, the ordered `send` loop) behind `TransportSender/TransportReceiver::Http { kind, .. }`; `client_tokio::start_http` bounds both starts by the connect timeout. Server-Sent Events (S8, D7/D27, JSON only): native `server_sent_events_tokio.rs` (streaming GET with `Accept: text/event-stream` and a 401 refresh; `EventStreamParser` per WHATWG with CRLF/LF/CR also split across reads, one BOM, comments ignored and not liveness, data joined with LF, the unfinished record bounded by `with_maximum_message_size` (line and data bytes after the last 0x1E, not discarded lines) -> `Protocol`; stream end or failure stops sends, sends ending first drop the stream, no DELETE); browser `browser_http.rs` `HttpTransport::start_server_sent_events` (`EventSource` wrapper detaching listeners on drop; the first error closes the source, no automatic reconnection, ending deferred with `spawn_local`; Bearer as `access_token` on the stream URL, `Authorization` on POSTs). Liveness over Server-Sent Events is as over WebSockets (pings, server timeout, initial Ping). Browsers use the default credentials mode (`fetch` same-origin, `EventSource` without `withCredentials`, D27). Long Polling (S7, D7) runs on both targets with both protocols: native `long_polling_tokio.rs` (one `process` task mirroring .NET `ProcessAsync`: a poll loop and a send loop, each with one hyper HTTP/1.1 `Lane` over `connect_tcp`/`tls_stream`; GET 200 frames, 204 ends, other statuses or errors drop the transport, 401/403 `Authentication`; ordered batched POSTs, one in flight; when the send side ends first the poll is dropped, a send failure is reported first, then a bounded best-effort DELETE; no DELETE after the server ended it; a request that fails unanswered on a reused connection is retried once on a fresh one, as `SocketsHttpHandler`) behind `TransportSender/TransportReceiver::LongPolling`; browser `browser_http.rs` `HttpTransport::start_long_polling` (`fetch` with an `AbortController` per request, body read before the request completes, `SocketEvent::Failed(Error)` before `Closed`, binary copied to a fresh `Uint8Array`, same DELETE rules). Credentials: `Authorization` header on every request (browsers too; `negotiation::http_transport_url` drops `access_token`), starting with `ConnectionRecipe::long_polling_authorization` (redirect/static credentials, else the negotiate token kept as `negotiated_authentication`), shared by polls, sends and DELETE, refreshed from the factory only after a 401 sent with the current value (.NET `AccessTokenHttpMessageHandler`): one factory call per connect, one more per 401. Bounds: native start `timeout(connect_timeout)` -> `Timeout(Connect)` (browser `start_transport` likewise); polls `long_polling_timeout` (100 s, the JavaScript client value) + connect timeout, a timed-out poll reissued (.NET re-polls after an `HttpClient` timeout); sends and DELETE the connect timeout. Inherent keep-alive: no keep-alive Pings and no server timeout over Long Polling (native `ConnectionLiveness::with_inherent_keep_alive`, browser `run_receiver`). Stateful Acks go out at most once per second and only for new messages (the receive loop wakes for the deadline); backpressure waits only while the buffer holds more than its size (an oversized frame is sent). A message is dispatched before its due Ack is sent (`common::Sequenced`); a failed send, Ack included, is an ordinary resumable loss, while any transport end with `ErrorKind::Protocol` disposes the stateful buffer (`common::ends_stateful_connection`) so the reconnect negotiates afresh. Native negotiate and WebSocket connections open their own TCP stream (`negotiate_http::connect_tcp`): every resolved address is tried in turn and `TCP_NODELAY` is set, so small frames (stateful Acks, Pings) never wait for delayed TCP acknowledgements; the stream is then wrapped with the connection's rustls connector and handed to `tokio-websockets` with `connect_on`. Connection setup on both targets (each negotiate request; natively TCP, TLS and the WebSocket upgrade; in browsers opening the WebSocket) is bounded by the configurable `with_connect_timeout` (`LivenessConfig::connect_timeout`, default 120 s like the official .NET client's negotiate bound, validated nonzero before I/O); the SignalR handshake keeps its own `handshake_timeout`. Browser negotiate uses `gloo-net` fetch on the global scope with an `AbortController` that aborts the request on timeout or when the caller stops waiting. Setup errors are typed: negotiate 401/403 are `Authentication` and other non-2xx `Negotiate` (both with `status()`), a negotiate `error` answer, unreadable body or redirect overflow is `Negotiate` without a status, a server without a usable transport is `TransportUnavailable`, exceeding the bound is `Timeout` naming `Negotiate` or `Connect`, an untrusted certificate is `Tls`, and DNS/TCP failures are `Transport`. Native sends complete once the transport accepts the message, like the .NET `SendAsync`: the caller reserves room in the bounded Tokio outbound queue that every handle shares, waits (on the connection's runtime, so any executor can await it) while the stateful replay buffer is full, and tracks and queues the frame under the replay buffer's lock, so sequence order is queue order; the writer task only writes, sends queued control frames (Acks) first, coalesces queued frames into WebSocket messages of at most 64 KiB, and closes the queue when it stops. A socket error after acceptance is not reported to that send (stateful replay or ordinary pending-work failure covers it); without stateful reconnect, frames queued at `disconnect`/`pause` can be dropped, like `StopAsync`. Against the official .NET client in the same Aspire run (S3, full scale) the release Rust client is at about 1.0x invoke latency and 1.0x send throughput, and 1.3-2.7x stream and fan-in throughput; latency margins are small and run-to-run noise (an emulator on the host) can exceed them. The browser transport (`client_wasm.rs` + `browser_socket.rs`) is event-driven: a small `web-sys` WebSocket wrapper whose listeners are detached with it feeds one generation-checked receiver task per socket; timers are cancellable `gloo-timers` futures; binary frames are copied out of shared wasm memory before `send` (threaded builds); nothing touches `window`, so it runs on the main thread, in Web Workers and in threaded (atomics) builds, with a `!Send` client per thread or worker.

Proxies (S9, D13, R8): every native connection (negotiate, WebSocket, Long Polling and Server-Sent Events `Lane`s) opens its TCP stream through `communication/proxy.rs::connect(config, secure, host, port)` under the connect timeout. `ProxyConfig` is `System` (default), `Explicit(ProxyUrl)` or `Disabled`. `System` resolves per connection as .NET `HttpEnvironmentProxy`: `https_proxy`/`HTTPS_PROXY` for secure endpoints, `http_proxy`/`HTTP_PROXY` for plain ones (`HTTP_PROXY` is ignored when `GATEWAY_INTERFACE` is set), else `all_proxy`/`ALL_PROXY`. Each value is parsed in turn, and empty or non-`http://` values are skipped with a warning. `no_proxy`/`NO_PROXY` bypasses use curl rules: hosts with subdomains, IPs, CIDR, `host:port` and `*`. A proxied connection opens an HTTP `CONNECT` tunnel, first without credentials. After a 407 that offers Basic, it retries on a fresh connection with Basic `Proxy-Authorization`. The response head is bounded at 16 KiB and bytes after it are an error. TLS with the connection's own rustls config then runs inside the tunnel. Failures are `ErrorKind::Proxy` (`Error::proxy`) with `status()`: 407 and 403 are not transient, while no status, 408, 429 and 5xx are. `ProxyUrl` percent-decodes credentials and redacts them in Display and Debug. Browsers always use the browser's proxy. Since S12 the connector is route-based (below).

Proxies since S12 (D13, R13), `proxy.rs`, `socks.rs`, `pac.rs`, `os_proxy.rs`:

- `proxy::connect(config, tls, secure, host, port) -> proxy::Stream` (`Tcp` or `ProxyTls`, the TLS session to an https:// proxy) walks `routes()`.
  - It connects TCP to each route first; only an unreachable route passes to the next. A reached proxy decides through `through()`, a CONNECT tunnel or `socks::tunnel_on`, so a 407/403 is final, as in .NET.
  - Endpoint TLS (`negotiate_http::tls_stream`, generic) and `WebSocketIo::Direct(MaybeTlsStream<proxy::Stream>)` run inside.
- Schemes (`ProxyScheme`):
  - `http` (port 80) and `https` (port 443): TLS to the proxy with a clone of the connection's ClientConfig with ALPN cleared; a handshake failure is `Proxy`.
  - `socks4`, `socks4a`, `socks5` and `socks5h` (port 1080), as .NET SocksHelper: socks5 and socks5h both send host names to the proxy (R13.C1 amended), socks4 resolves locally to IPv4 and maps IPv4-mapped IPv6, and 4a resolves at the proxy. RFC 1929; a ruleset refusal is 403 and refused credentials 407.
- `ProxyConfig`:
  - `System` (default): the environment when `environment_configured` (any usable http/https/all proxy variable), else the OS reader, else the environment.
  - `Os` (`with_os_proxy`), `Explicit`, `Disabled`.
  - `AutoConfig(PacConfig)` under the `rayx_pac` cfg (build.rs: the proxy-pac feature on native targets except iOS, where Boa's time/num_threads fails with libc 0.2.190).
- PAC (Boa 0.22, `with_proxy_auto_config`):
  - The script is loaded directly once per start (`ProxyConfig::begin_connect` from client_tokio start); file/http/https, 1 MiB.
  - Evaluation: `Script::evaluate_async_with_budget(10_000)` polled against a 5 s deadline, the loop limit 1M, at most 8 concurrent (Condvar wait).
  - DNS helpers are cached per evaluation, wait at most 2 s and never past the deadline; lookup threads are capped at 16.
  - Results: PROXY/HTTP/HTTPS/SOCKS(=4)/SOCKS4/SOCKS5/DIRECT.
- OS readers return `Vec<Route>`; a read failure gives DIRECT (.NET):
  - WinHTTP: IE config, then WinHttpGetProxyForUrl on a static session (no logon first, retry on LOGIN_FAILURE); DIRECT is final; the manual fallback only when it fails; auto-detect backoff 120 s; loopback always direct; proxy lists as .NET MultiProxy (socks= skipped).
  - CFNetwork: CopyProxiesForURL, with PAC executed by `CFNetworkExecuteProxyAutoConfigurationURL/Script` on a private run-loop mode (10 s), so iOS has system PAC without Boa.
  - Android: JNI ProxySelector with the JavaVM stored by `tls::android::init_with_env`.
  - Linux: the environment.
- Runtime proof: `proxy-socks`, `proxy-https` and `proxy-pac` (native, Android) and `os-proxy` (android-app; Windows/macOS cells only on opted-in CI, S15). The Apple code is compile-checked only.

Since S11 `aws-lc-rs` and the Android platform verifier have runtime proof. With `aws-lc-rs` the TLS-dependent scenarios (`tls`, `connect-negotiate`, `negotiate-redirect`, `proxy`) pass on native and Android. The verifier runs after `init_with_env` inside the test app, in a debug and a minified release APK. On Android the platform verifier trusts system and user CAs (`AndroidCAStore`), not the app's network security config.

Cookies and client certificates (P6, D22).

- Cookie jar (`communication/cookies.rs`, native):
  - The public `CookieJar` (clones share it; `Debug` shows only a count) serves as .NET's `HttpConnectionOptions.Cookies`; by default each configuration has its own (`with_cookie_jar` shares one), cloned into `ConnectionRecipe.cookies`.
  - It follows an RFC 6265 subset (host-only and `Domain` matching, where a dot-less domain must equal the host; path match; `Secure`; `Max-Age` over `Expires` with a lenient date parser; token names and header-safe values) with the .NET limits of 4096 B, 20 per domain and 300 total.
  - It is applied by `headers::with_cookies` (after an application `Cookie` header) and stored from every response (`store_response`) on negotiate (including errors), the upgrade (including stateful resumes) and `http_transport` `Lane` requests.
- Client certificates: `with_client_certificate(chain_pem, key_pem)` maps to `TlsSettings.client_certificate`, parsed at `new` into `PreparedTls`, and `build_config` uses `with_client_auth_cert`. Errors are `Configuration` naming `with_client_certificate` and never echo the key.
- TLS error classification: `tls::is_tls_failure`/`classify` map rustls errors found in a source chain to `ErrorKind::Tls` (negotiate handshake, send and body, and the upgrade), covering TLS 1.3 refusals reported after the handshake.

Integrated Windows authentication (P7, D23), `communication/integrated_auth/`:

- API: `with_default_credentials()` and `with_credentials(user, password, domain)` produce `IntegratedCredentials`. `provider()` returns `SspiProvider` on Windows or `NtlmProvider` elsewhere; `Default` outside Windows fails `new` with `Configuration`. The provider is kept as `ConnectionRecipe::integrated`.
- Connections: one HTTP/1.1 connection helper, `negotiate_http::http1(Endpoint, bound, upgrades, handshake_error)`, serves negotiate, `Lane` (which keeps an `integrated_auth::Connection` holding the sender and its binding) and the authenticated upgrade. It runs through the proxy and TLS and computes the RFC 5929 `tls-server-end-point` binding from the rustls peer certificate when bound.
- Exchange: `integrated_auth::send(connection, provider, host, reconnect, observe, build)` follows `SocketsHttpHandler` NtAuth:
  - The first request goes out without credentials. A 401 offering Negotiate (preferred) or NTLM is answered on the same connection after draining the body (up to 1 MiB; larger fails `Authentication` because the connection cannot be reused), or on a `reconnect()` connection after `Connection: close`.
  - Each leg is rebuilt with the jar's current cookies, and `observe` stores every response's cookies.
  - A context that cannot start, or a failed step, returns the 401. A final token on success (Kerberos mutual authentication) is validated, and a failure is `Authentication` 401.
  - `context` and `step` run in `spawn_blocking`.
- WebSocket upgrade: with a provider, it goes through hyper (`upgrade_authenticated`): the key comes from getrandom, `Sec-WebSocket-Accept` is checked, then `take_over` wraps `WebSocketIo::Upgraded`. Without a provider the tokio-websockets path is unchanged.
- SSPI (`sspi.rs`): the SPN is `HTTP/<canonical_host>` (GetAddrInfoW with `AI_CANONNAME`; IPs and failed lookups are kept as given). It requests `ISC_REQ_CONNECTION|INTEGRITY` and requires `ISC_RET_INTEGRITY` (.NET `ProtectionLevel.Sign`), passes `SECBUFFER_CHANNEL_BINDINGS` on every call, and frees the output through a guard.
- Managed NTLMv2 (`ntlm.rs`, as .NET's managed NTLM):
  - Negotiates SIGN, KEY_EXCH and VERSION (6.1.7600 rev 15) and requires SIGN in the challenge.
  - Sends an RC4-encrypted random exported key; the MIC uses the exported key when the server sends a timestamp.
  - Adds MsvAvChannelBindings (MD5 of the gss struct, or Z16) and MsvAvTargetName.
  - The target name outside Windows is not canonicalized (a documented limitation).
- Proof:
  - The `integrated_auth_` unit groups: scripted exchanges, MS-NLMP vectors, and the Windows-only `integrated_auth_sspi` acceptor tests (channel bindings accepted or `SEC_E_BAD_BINDINGS`, managed and explicit-credential NTLM `SEC_E_LOGON_DENIED`).
  - The native `windows-auth` scenario. Kerberos has no runtime proof (the host has no domain).

Transport hooks (P8, D22), `communication/request_hook.rs`:

- `request_hook::apply` runs the hook once per logical request, as a .NET factory handler sees one `SendAsync`: on composed headers (defaults, `with_header`, the credentials' `Authorization`, plus `Content-Type`).
- `headers::leg` then adds the jar's cookies and integrated tokens per leg.
- Call sites:
  - Native negotiate: `negotiate_http::Options` (`Options::of(recipe)`).
  - Both upgrade paths.
  - `Lane::prepare` (`request`/`open_stream`); a retry reuses the prepared headers.
  - Browsers: `common::fetch_text` and `browser_http::request_once`, with `Content-Type` before the hook.
- TLS hook: `TlsSettings.config_hook` -> `PreparedTls`, applied in `TlsContext::config` after `build_config` and outside the slot lock (`get_or_insert`).

HTTP/2 (S13, D14, R14), `communication/http2.rs`:

- `HttpVersion` (`Http1`, `Auto` default, `Http2`); `ConnectionRecipe::http_version()` returns `Http1` whenever integrated authentication is configured (as .NET skips `Http2HttpMessageHandler` with credentials), so `Http2` + credentials lowers silently.
- ALPN: `TlsContext::config_with_alpn` derives one config per offer from the connection's (hook included) and replaces its `alpn_protocols` (`Auto` = `h2, http/1.1`, `Http2` = `h2`); the HTTP/1.1 WebSocket and `Http1` keep the connection's own offer. Proxy TLS clears ALPN.
- `negotiate_http::open(endpoint, version, ..) -> Opened::{Http1, Http2}`: h2c prior knowledge for plaintext `Http2`, ALPN check over TLS (`Http2` without `h2` = `Transport` "did not negotiate HTTP/2"); runs through every proxy route.
- `http2::Pool` (recipe-shared `Arc`) keys senders by (host, port, secure); negotiate, the `Lane`s (`http1_chosen` remembers an HTTP/1.1 choice) and `CommunicationClient::upgrade_http2` (RFC 8441 extended CONNECT, `Http2` only) share it. Cleared by `attempt_once` before every fresh connect (start and reconnect) and by `close_locally`; a stateful resume keeps it.
- `http2::send` uses `try_send_request`; `SendFailure.retry` only when unsent, `REFUSED_STREAM`, or a remote graceful `GOAWAY` — every caller retries once on a new connection, never a processed request. No keep-alive pings (.NET default off).
- Proof: the `http2_` unit group (14) and the native/Android `http2` scenario.

Experimental HTTP/3 (S14, D15, R15), `communication/http3.rs`, feature `http3` (`rayx_http3` = `http3` + `rayx_tls`):

- quinn 0.11 (runtime-tokio; crypto from the provider features via `quinn?/rustls-*`), h3 0.0.8, h3-quinn 0.0.10. QUIC config = `TlsContext::config_with_alpn(h3)` (explicit provider, verifier, hook); 15 s keep-alive; crypto transport codes 0x100..0x200 = `Tls`.
- `http3::connection`: plaintext or first route through a proxy = `Transport` under `Http3`, TCP under `Http3Preferred`; Preferred gives QUIC half the bound, then `Pool::use_tcp` for the attempt. `http2::Pool` also keeps HTTP/3 connections.
- `http3::exchange` retries once only when `send_request` failed (stream never opened) and forgets the failed connection. Negotiate `post` and `Lane::exchange_http3` (request/open_stream) try it before HTTP/2; streamed bodies are `ResponseBody{Hyper, Http3(Box)}` read with `chunk()`.
- WebSockets never over HTTP/3: Kestrel 10 advertises no `SETTINGS_ENABLE_CONNECT_PROTOCOL` for HTTP/3 (WebTransport only). `TransportSelection::over_http3` skips them under strict `Http3`; `open_websocket` refuses it. Not a .NET parity feature (the .NET SignalR client pins HTTP/2-or-lower).
- Proof: `http3_` unit group (7, in-process quinn+h3 server) and the native/Android `http3` scenario.
